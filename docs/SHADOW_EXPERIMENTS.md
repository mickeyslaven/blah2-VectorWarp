# Shadow experiment registry

This is the operational registry for passive, counterfactual paths. A row is
diagnostic unless its acceptance field explicitly says otherwise. It does not
authorize a configuration change, service enablement, or a production claim.

| Class and path | Status | Evidence | Acceptance | Heartbeat freshness check |
| --- | --- | --- | --- | --- |
| Continuous — detection-manifold corpus: `api/detection-manifold-automation.js` and `api/detection-manifold-corpus.js` | Default-off collection; current replay comparison is diagnostic only. | Immutable corpus fingerprint, pass/sector coverage, accepted/rejected rows, same-IQ nuisance rows, and gain/config identity. | No runtime candidate or promotion until a separate authenticated raw-IQ exporter, pass-disjoint physical cohort, and complete production-replay gate exist. | Check collection/status timestamps advance only for the current receiver/config/gain epoch; reject stale corpus or mixed fingerprints. |
| Continuous — bearing-manifold and fixed-transmitter corpus: `api/manifold-recorder.js`, `api/manifold-automation.js` | Default-off recorder/fit evidence; no measured bearing model is active by default. | Aircraft response corpus plus separate fixed-transmitter anchor, configuration fingerprint, sector/pass coverage, and fit diagnostics. | Require independent pass/sector coverage and the documented held-out bearing gate before any separate authorization. | Check recorder and anchor timestamps, source fingerprints, and acceptance/rejection counters; an old anchor or a changed site identity is not current evidence. |
| Continuous — frequency-resolved observer: `api/frequency-resolved-shadow.js` | Default-off API-owned worker. The API is the sole scheduler and owns one bounded Heimdall/MCHQ client when enabled. | Atomic output, fingerprint, sequence, worker error, and stability-from-previous result. | Diagnostic only; a separate processor implementation and held-out ADS-B comparison are required for promotion. | Check `lastAnalysisAt`, `active`, `error`, output fingerprint, and sequence against the live config epoch. Do not add a timer or second polling client. |
| Continuous/per-pass — forthcoming truth-selected below-threshold export | Not implemented; reserved as a per-pass evidence lane, not a detector path. | When implemented, require immutable sample-range/provenance bindings, one declared target CUT per pass, baseline outcome (`miss` or `subthreshold`), and no truth-selected beam. | It must remain diagnostic until raw-IQ-derived complete grids and the detection-manifold production gate accept a pass-disjoint cohort. | Check that a new export is tied to the current pass and immutable receipt; missing, stale, or mixed-epoch rows are not evidence. |
| Strix on-demand — integration sensitivity: `api/integration-shadow-queue.js`, `script/run-integration-sensitivity-shadow.py` | The API writes bounded immutable jobs; an external worker (normally Strix) performs replay and refuses the live producer host. | Signed job/result identity, IQ/admission/config digests, queue/claim state, wall-time bound, and per-arm denominator. | No detector promotion; outputs can only guide a later held-out experiment. | Check queue age/depth, unclaimed or expired jobs, result receipt/HMAC identity, and that no worker is the live producer. |
| Strix on-demand — motion-compensated trajectory integration: `script/analyze-exact-trajectory-stack.py`, `script/analyze-coherent-trajectory.py` | Offline replay analysis only. | Exact replay/admission identity, truth/CPI alignment, complex-cutout provenance, and trajectory/phase diagnostics. | Never infer a production detector change from an offline stack; require a separately specified, held-out acceptance plan. | Check replay and admission digest match, pass identity, input age, and that results are not presented as live processor output. |
| Strix on-demand — detection-manifold A/B: `script/evaluate-detection-manifold-replay.py`, `api/detection-manifold-fitter.js` | Diagnostic replay only; the current post-CAF tool is not an authenticated raw-IQ production evaluator. | Frozen corpus hash, arms, per-pass target/nuisance outcomes, CFAR context, and unsupported-support report. | The runtime arm remains disabled until the raw-IQ production receipt and physical holdout criteria pass. | Check candidate/corpus fingerprint, replay completion time, pass-disjoint split, and unresolved blockers. |
| Strix on-demand — bearing diagnostic/replay: `api/bearing-diagnostic.js`, `api/bearing-diagnostic-cache.js`, `script/fit-bearing-manifold.js` | Read-only diagnostic/replay; it may evaluate evidence while live detection uses another fusion mode. | Evidence schema/version, covariance and physical response data, calibration fingerprint, fit error, and sector coverage. | No model activation or geometry change; require independent held-out evidence and an explicitly authorized deployment. | Check diagnostic cache age, source corpus fingerprint/schema, fit timestamp, and error state before treating any result as current. |
| Production-excluded compatibility — external tracker: `api/tracker-forward.js`, `api/tracker-publication.js` | Optional API compatibility only. `config/config-kraken.yml` sets `network.tracker_forward.enabled: false`; no disconnected feed or endpoint starts by default. | Forwarder/publication counters, explicit endpoint configuration, and external event-file freshness. | An administrator must explicitly configure and review the optional sidecar; it is not a shadow evidence lane. | Check disabled state by default; if explicitly enabled, check connection/event-file freshness and stale fallback. |

The registry deliberately excludes promoted track-guided/TBD paths and any
active production processor path. Those are not shadows once they can affect
authoritative detection, association, tracking, or publication, and require a
separate production change and acceptance record.

Heartbeat policy: report only a material transition—new evidence, stalled or
stale evidence, a failed acceptance condition, an identity mismatch, a bounded
queue problem, or a required operator decision. It must not treat a status
endpoint response alone as fresh evidence; freshness is the recorded timestamp
plus the matching immutable config/receiver/gain/pass identity described above.
